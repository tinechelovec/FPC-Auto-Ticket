# 🎫 Auto Ticket — инструкция по установке и настройке

Привет! Это альтернативная инструкция для **Auto Ticket** — плагина для FunPay Cardinal, который автоматизирует работу со старыми активными заказами и создание тикетов в поддержку FunPay.

Плагин собирает подходящие заказы, ждёт указанное вами время, при необходимости анализирует переписку с покупателем и формирует тикеты в поддержку.

> Основная инструкция: https://teletype.media/@tinechelovec/Auto-Ticket
> GitHub: https://github.com/tinechelovec/FPC-Auto-Ticket

---

# 📌 Что делает Auto Ticket

Плагин умеет:

* автоматически находить активные оплаченные заказы;
* сохранять найденные заказы в локальную базу;
* ждать заданное количество часов после покупки;
* создавать тикеты в поддержку FunPay;
* объединять несколько заказов в один тикет;
* разделять заказы по их состоянию;
* анализировать переписку с покупателем;
* работать полностью локально без AI;
* использовать **io.net AI** для более подробного анализа;
* автоматически писать покупателю перед созданием тикета;
* пропускать заказы, находящиеся в арбитраже;
* устанавливать отдельное время ожидания для конкретных лотов;
* вручную отправлять тикет по одному заказу;
* добавлять отдельные заказы в игнор;
* автоматически получать PHPSESSID;
* работать по расписанию в фоне;
* отправлять уведомления в Telegram;
* сохранять настройки, базу заказов и логи;
* создавать резервную копию;
* обновляться через интерфейс плагина.

# 🚀 Установка

Для работы плагина нужен установленный **FunPay Cardinal**.

После установки Cardinal:

1. скачайте актуальный файл Auto Ticket;
2. откройте Telegram-бота Cardinal;
3. отправьте:

```text
/menu
```

4. перейдите в раздел **«Плагины»**;
5. загрузите файл Auto Ticket;
6. после установки откройте плагин из списка.

Выполняет проверку основных компонентов:

* локального хранилища;

При этой проверке **реальный тикет не создаётся**.

# 🔐 Авторизация

Для создания тикетов Auto Ticket должен иметь действующую авторизацию на сайте поддержки FunPay.

Для этого используется:

```text
PHPSESSID
```

Есть два варианта его настройки.

---

## 🔄 Получать PHPSESSID автоматически

По умолчанию плагин может самостоятельно получать актуальный PHPSESSID при запуске Cardinal.

Для этого используется авторизация вашего FunPay-аккаунта, уже подключённого к Cardinal.

Это самый удобный режим, потому что вам не нужно регулярно обновлять PHPSESSID вручную.

---

## ✏️ Ввести PHPSESSID вручную

Если автоматическое получение вам не подходит, PHPSESSID можно указать вручную.

После сохранения плагин будет использовать его для авторизации на:

```text
support.funpay.com
```

---

## 🧹 Очистить

Удаляет сохранённый PHPSESSID.

---

## 🩺 Проверить авторизацию

Проверяет, может ли плагин авторизоваться на сайте поддержки FunPay.

Перед использованием автоматической отправки тикетов рекомендуется обязательно выполнить эту проверку.

> ⚠️ **PHPSESSID — это чувствительные данные вашего аккаунта.**
>
> Не отправляйте его посторонним людям и не публикуйте в открытом доступе.

# 🎛 Режимы и тексты

Auto Ticket поддерживает три режима обработки заказов:

1. **Один список**
2. **Локальный анализ**
3. **io.net AI**

Режим определяет, как плагин будет анализировать заказы перед отправкой в поддержку и какие тексты тикетов будут использоваться.

---

# 1️⃣ Один список

Самый простой режим.

Плагин не пытается разделять заказы по типу ситуации.

Все подходящие заказы собираются в один общий список и отправляются с одним шаблоном сообщения.

Пример стандартного текста:

```text
Здравствуйте!

Прошу подтвердить выполнение следующих заказов:
{orders}

Заранее благодарю.
С уважением, {username}.
```

Этот режим подойдёт, если вам не нужен анализ переписки и вы хотите максимально простую автоматизацию.

---

# 2️⃣ Локальный анализ

В этом режиме Auto Ticket анализирует сохранённую переписку **локально, без внешнего AI API**.

Заказы разделяются на три категории:

* **✅ Подтверждённые**
* **❌ Проблемные**
* **❓ Неоднозначные**

Для каждой категории можно установить отдельный текст тикета.

---

## ✅ Подтверждённые

Плагин нашёл признаки того, что:

* продавец выполнил заказ;
* покупатель получил товар;
* покупатель подтвердил выполнение;
* в переписке нет нерешённой проблемы.

Для таких заказов используется отдельный шаблон.

---

## ❌ Проблемные

В переписке обнаружены признаки проблемы.

Например:

* покупатель пишет, что товар не работает;
* товар не получен;
* есть жалоба;
* обсуждается возврат;
* присутствуют сообщения об ошибке;
* есть другие признаки нерешённой ситуации.

Такие заказы отправляются в отдельном тикете с текстом для проблемных заказов.

---

## ❓ Неоднозначные

Плагин не смог однозначно определить ситуацию.

Например:

* данных в переписке недостаточно;
* сообщения противоречат друг другу;
* нет явного подтверждения;
* нет явной проблемы.

Такие заказы можно отправлять в поддержку отдельно.

---

# 🔎 Локальные признаки

Для режима локального анализа можно настроить слова и фразы, которые будут считаться признаками проблемного заказа.

Например:

```text
проблем
не работает
возврат
не получил
ошибка
жалоба
refund
error
failed
```

Если стандартного списка недостаточно, его можно изменить под свои товары и покупателей.

---

# ♻️ Переклассифицировать базу

После изменения режима анализа или локальных признаков можно заново обработать уже сохранённые заказы.

Кнопка:

**♻️ Переклассифицировать базу**

повторно анализирует заказы и обновляет их категории.

---

# 3️⃣ io.net AI

Это самый продвинутый режим.

Auto Ticket отправляет информацию о заказах и переписке в **io.net AI**, после чего модель определяет ситуацию по каждому заказу.

Заказы также делятся на:

* **✅ подтверждённые**
* **❌ проблемные**
* **❓ неоднозначные**

Но решение принимает AI с учётом большего количества контекста.

---

# 🤖 Настройки io.net AI

В этом разделе можно настроить:

* API-ключ;
* модель;
* проверить работу API.

---

## 🔑 API-ключ

Для использования AI-режима необходимо добавить API-ключ io.net.

Без рабочего API-ключа AI-классификация работать не будет.

---

## 🧠 Выбрать модель

Плагин может загрузить список доступных моделей io.net.

После этого можно выбрать нужную модель прямо из Telegram-интерфейса.

По умолчанию в плагине указана модель:

```text
meta-llama/Llama-3.3-70B-Instruct
```

При необходимости её можно заменить другой доступной моделью.

---

## 🩺 Проверить API

Кнопка отправляет тестовый запрос и проверяет, отвечает ли выбранная модель.

Реальные тикеты во время этой проверки не создаются.

---

# 💬 Авто-сообщения покупателям

Auto Ticket может автоматически написать покупателю перед отправкой заказа в тикет.

Логика нужна для ситуации, когда с вашей стороны заказ уже выполнен, но покупатель его ещё не подтвердил.

Стандартный текст примерно такой:

```text
Здравствуйте! По заказу #{order_id} с нашей стороны выполнение отмечено завершённым.

Если всё получено и работает, пожалуйста, подтвердите заказ.

Если есть вопрос или проблема — напишите здесь, я учту это и не буду торопить с подтверждением.
```

Плагин не должен отправлять такое сообщение, если:

* заказ уже завершён;
* заказ находится в игноре;
* обнаружена нерешённая проблема;
* заказ находится в арбитраже;
* покупатель уже подтвердил получение;
* нет признаков того, что продавец выполнил заказ.

По умолчанию сообщение отправляется не сразу после выполнения, а после небольшой задержки.

---

# 📝 Тексты тикетов

Для разных режимов доступны разные шаблоны.

## Один список

Используется один общий текст.

## Локальный анализ / AI

Используются отдельные тексты:

* подтверждённых заказов;
* проблемных заказов;
* неоднозначных заказов.

В текстах можно использовать переменные:

```text
{orders}
{username}
{count}
{classification}
```

### `{orders}`

Список номеров заказов.

Например:

```text
#ABC123, #DEF456, #QWE789
```

### `{username}`

Ваш FunPay username.

### `{count}`

Количество заказов в текущем тикете.

### `{classification}`

Категория заказов.

# 🔎 Интервал сканирования

Определяет, как часто Auto Ticket проверяет список ваших активных заказов.

По умолчанию:

```text
1 час
```

Плагин загружает актуальные оплаченные заказы и обновляет локальную базу.

---

# 📨 Интервал отправки

Определяет, как часто плагин будет запускать автоматическую отправку готовых тикетов.

По умолчанию:

```text
24 часа
```

Это не означает, что любой новый заказ будет отправлен через 24 часа.

Для этого отдельно используется **возраст заказа**.

---

# ⌛ Общее время заказа

Это минимальное время, которое должно пройти после покупки, прежде чем заказ станет подходящим для тикета.

По умолчанию:

```text
24 часа
```

Пример:

покупатель оформил заказ в 12:00.

Если общее время установлено на 24 часа, раньше 12:00 следующего дня этот заказ автоматически в тикет не попадёт.

---

# 🎯 Исключения для лотов

Для отдельных товаров можно установить другое время ожидания.

Например:

общая настройка:

```text
24 часа
```

но для конкретного лота вам нужно ждать:

```text
72 часа
```

Тогда можно создать отдельное правило для этого LOT ID.

---

## ➕ Добавить лот

Отправьте FunPay LOT ID.

Например:

```text

```

Плагин найдёт ваш лот и создаст для него индивидуальное правило.

После этого указывается отдельное время ожидания.

---

## ✏️ Изменить время

Для уже добавленного исключения можно поменять количество часов.

---

## 🗑 Удалить исключение

После удаления лот снова начинает использовать общее время заказа.

---

# 📦 Заказов в одном тикете

Определяет максимальное количество заказов, которые Auto Ticket попытается объединить в один тикет.

По умолчанию:

```text

```

Если заказов больше или текст тикета становится слишком большим, плагин может разделить их на несколько тикетов.

# 🔁 После запуска Cardinal

Можно выбрать два варианта поведения.

## ПРОДОЛЖИТЬ ТАЙМЕР

После перезапуска Cardinal плагин продолжает работать по расписанию и не отправляет тикеты сразу.

Это более безопасный вариант.

## ОТПРАВИТЬ СРАЗУ

После запуска плагин может сразу проверить и отправить уже готовые подходящие заказы.

Используйте этот вариант внимательно.

---

# 🔎 Сканировать сейчас

Запускает ручное сканирование заказов.

Плагин:

1. получает актуальный список активных заказов;
2. обновляет локальную базу;
3. добавляет новые заказы;
4. отмечает уже завершённые;
5. обновляет информацию и контекст.

Эта кнопка не меняет установленный интервал автоматического сканирования.

---

# 🎫 Отправить тикеты сейчас

Запускает ручной цикл отправки.

Плагин выбирает заказы, которые:

* не находятся в игноре;
* всё ещё активны;
* уже достигли необходимого возраста;
* ещё не отправлялись;
* не находятся в арбитраже, если включён его пропуск.

После этого создаются тикеты согласно выбранному режиму.

Эта кнопка также не меняет автоматический интервал.

---

# 🔄 Как работает автоматический цикл

В обычном режиме процесс выглядит примерно так:

1. Auto Ticket сканирует активные заказы.
2. Новые заказы сохраняются в локальную базу.
3. Для заказов собираются доступные данные и переписка.
4. Плагин ждёт указанное количество часов.
5. При необходимости заказ анализируется.
6. Если включены авто-сообщения, покупателю может быть отправлено сообщение.
7. Заказы в игноре пропускаются.
8. Заказы в арбитраже могут быть пропущены.
9. Готовые заказы группируются.
10. Формируется текст тикета.
11. Плагин авторизуется на сайте поддержки.
12. Создаётся тикет.
13. В базе сохраняется информация об успешной отправке.
14. Следующий цикл выполняется по установленному интервалу.

## 🌐 Онлайн-обновление

# ❓ Если тикеты не отправляются

Проверьте по порядку:

1. включён ли Auto Ticket;
2. работает ли фоновый обработчик;
3. есть ли сохранённый PHPSESSID;
4. проходит ли **«Проверить авторизацию»**;
5. выполнялось ли сканирование заказов;
6. есть ли нужный заказ в разделе **«Заказы»**;
7. достиг ли заказ установленного возраста;
8. не добавлен ли заказ в игнор;
9. не находится ли он в арбитраже;
10. не отправлялся ли он уже;
11. правильно ли настроен текст тикета;
12. если используется AI — работает ли io.net API;
13. что написано в `log.txt`.

# ✅ Рекомендуемая первая настройка

Если используете Auto Ticket впервые:

1. установите плагин;
2. откройте **«Авторизация»**;
3. включите автоматическое получение PHPSESSID;
4. нажмите **«Проверить авторизацию»**;
5. выберите режим **«Один список»**;
6. оставьте стандартный текст;
7. установите достаточно большой возраст заказа для тестирования;
8. нажмите **«Сканировать сейчас»**;
9. посмотрите найденные заказы вручную;
10. добавьте ненужные заказы в игнор;
11. только после проверки запускайте автоматическую отправку.

Когда убедитесь, что базовый режим работает правильно, можно переходить к локальному анализу или io.net AI.
